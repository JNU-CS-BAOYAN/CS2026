## 通过 PR 投稿（当前为 2026 年）

1. 下载上方 Markdown 模板，将文件保存为 `index.md`，填写 YAML 中的必填字段和正文。可选字段不用填写时，保留注释或删除即可。
2. Fork [项目仓库](https://github.com/JNU-CS-BAOYAN/CS2026)，在自己的仓库中创建分支。
3. **当前新稿统一放在 `src/content/experiences/2026/<文章ID>/`**。文章 ID 使用不重复的英文小写字母、数字或连字符，例如 `xiaojiang`。将 `index.md`、封面和正文插图一起放进这个文件夹。
4. 在 `index.md` 中填写 `applicationYear: 2026`，确保与目录一致；院校使用全称，本科专业按实际情况填写。不要修改其他人的文章。
5. 提交整个文件夹，向原仓库的 `main` 分支[发起 PR](https://github.com/JNU-CS-BAOYAN/CS2026/compare)，说明署名和图片的公开授权。如需补充历史年份的经历，请放在对应年份目录，并使用相同的 `applicationYear`。

投稿文件夹示例：

```text
src/content/experiences/2026/xiaojiang(与author字段相同)/
├── index.md        # 必需：YAML 文件头和完整经验正文
├── cover.jpg       # 可选：文章封面
├── interview.png   # 可选：正文插图
└── timeline.webp   # 可选：其他正文插图
```

**一位投稿者提交一篇完整经验贴**，夏令营、预推免和其他申请经历在同一篇文章中分章节记录，不需要分成多篇。

模板参考原站结构：个人背景使用表格，夏令营与预推免各有一张院校经历汇总表，表格下方可以继续写各院校的详细经历。没有参加某一阶段时，可以删除对应章节。正文不用手写目录，网站会根据标题自动生成左侧目录。

维护者审核并合并到 `main` 后，网站会自动检查、构建和部署。提交 PR 或审核通过本身不会发布文章。

## 封面与正文插图

有封面时，在 YAML 中填写：

```yaml
cover: "./cover.jpg"
```

文件名和扩展名须与实际文件一致，也可以使用 PNG 或 WebP。封面用于经验卡片和文章页顶部，**不会自动插入正文**。没有封面时，网站使用项目图片池，图片池见`src/assets/cover-pool`。

正文插图用相对路径引用同目录文件：

```markdown
![面试流程示意](./interview.png)
![申请时间线](./timeline.webp)
![其他图片](./other.jpg)
```

正文插图不作为卡片封面。无需修改 Astro 页面，也无需另外登记图片；文件随整个文件夹提交，路径及大小写对应即可。注意不要使用电脑上的绝对路径。

## YAML 字段说明

下载模板中已列出投稿需要填写的字段并提供注释，`publishedAt` 由维护者发布前补充。以下三个字段必填，其他字段均可省略：

| 字段 | 是否必填 | 用途 |
| --- | --- | --- |
| `title` | 必填 | 文章标题，在卡片和文章页显示 |
| `author` | 必填 | 作者署名，可用真实姓名、昵称或“匿名” |
| `applicationYear` | 必填 | 申请年份，决定年份归档，必须与目录一致，当前是2026 |
| `undergraduateMajor` | 选填 | 本科专业，在卡片、文章页和搜索结果显示 |
| `institutions` | 选填 | 涉及院校的全称列表，以标签显示，并支持搜索，学校全称 |
| `cover` | 选填 | 封面相对路径，省略时使用图片池 |
| `sourceUrl` | 选填 | 原始出处的完整 URL，用于来源记录 |
| `publishedAt` | 选填，由维护者核对 | 本站首次发布时间，用于“最新收录”排序，文章页显示，卡片不显示 |
| `finalDestination` | 选填 | 最终去向，在文章页显示 |

涉及院校填写、实际申请或参与考核的院校全称；最终去向填写最后的选择，两者分别记录。。

`publishedAt` 是本站首次发布时间，不是申请年份或原文在其他平台的发表时间，普通修订不更新。院校标签统一使用全称，搜索仍支持常见简称。

封面的图片替代文字由文章标题自动生成，无需额外填写。投稿是否发布由维护者审核与 PR 合并控制，不需要设置草稿字段。

## 通过邮箱投稿

不熟悉 GitHub 也没关系。按同一份 Markdown 模板填写 `index.md`，将它与封面、正文插图放在同一文件夹，打包后发送到 [eeecank@163.com](mailto:eeecank@163.com)。请在邮件中注明申请年份、署名及图片的公开授权；对 YAML 有疑问可在邮件中说明，由维护者协助核对。

经验正文统一使用 Markdown。邮箱与 PR 两种渠道使用相同的文件结构和模板。

## 投稿前请确认

1. 必填字段已填写，YAML 使用空格缩进，年份与目录一致，未填写的正文占位、示例表格行和不适用的章节已删除。
2. 内容来自亲身经历，尽量清晰、有条理；允许匿名，不要求学号、精确排名或私人联系方式。
3. 封面与正文插图路径正确，图片允许公开，私人信息已脱敏。
4. 如另有简历、个人陈述等资料，希望公开时请在 PR 或邮件中单独说明，等待维护者审核；普通附件链接不会像 Markdown 图片一样自动处理，发布前需要核对。
5. 如希望加入贡献者列表，可同时提供 GitHub 个人主页链接，头像由维护者补充。

模板中的 `<!-- ... -->` 是 HTML 注释，网页正文不会显示，填写提示可以保留，也可以删除。YAML 中以 `#` 开头的行也是注释，不会成为字段；需要启用某个选填字段时，删除该行开头的 `#` 并填写实际内容。若要展示注释中的图片示例，请保留图片语句、去掉外层 `<!--` 和 `-->`，再填写正确的图片路径。

更正、撤下或其他问题可通过 [Issue](https://github.com/JNU-CS-BAOYAN/CS2026/issues) 或[邮箱](mailto:eeecank@163.com)联系。
